## Why

Foundation #4 adds an on-device **Gemma-4 E2B multimodal** pass (react-native-executorch) as a heavy **Tier-1** workload — a ~3.2 GB (iOS MLX) / ~4.4 GB (Android Vulkan) model doing sustained GPU inference. Two device realities must gate it that the existing battery+night gating (`BackgroundTaskService.shouldPauseProcessing`, left as a seam by #3) does not cover: (1) **not every device can run it at all** — a low-RAM / low-disk / non-arm64 phone will OOM or thrash, so it must silently stay on Tier-0; and (2) **even a capable device must back off when it gets hot** — sustained inference overheats the SoC and the OS throttles or jetsams us. This change adds a **device-capability gate** (eligibility: may Tier-1 ever run here?) and a **thermal gate** (pressure: may a heavy pass run *right now?*), **layered onto** the existing gating without a rewrite. It ships the gate infrastructure only; wiring Gemma into a Tier-1 drain is #4's job.

## What Changes

- **Capability gate (JS-only, no native work).** A new all-static `DeviceCapabilityService` uses **`react-native-device-info`** (already a dependency, `package.json:40`, used today in `src/utils/device/battery.ts`) — `getTotalMemory()`, `getFreeDiskStorage()`, `supportedAbis()`, `isLowRamDevice()`, `getDeviceId()`/`getModel()` — to compute a **coarse Tier-1 eligibility policy** (default floor: total RAM ≥ **6 GiB**, live free disk ≥ **6 GiB**, `arm64-v8a` present on Android, not a low-RAM device). A device that fails the gate **silently runs Tier-0 only, never Tier-1**. The static class verdict is cached (MMKV); free disk is re-checked live.
- **Thermal gate (new native TurboModule + JS wrapper).** `react-native-device-info` exposes **no** thermal API, so add a small **`ThermalObserver` TurboModule** mirroring the existing `MediaObserver` pattern (`src/native-modules/NativeMediaObserver.ts`, `android/.../mediaobserver/*`, `ios/Visara/MediaObserver/*`). It exposes, on **both** platforms, **a getter + a change event**: iOS via `ProcessInfo.processInfo.thermalState` + `ProcessInfo.thermalStateDidChangeNotification`; Android via `PowerManager.getCurrentThermalStatus()` + `PowerManager.addThermalStatusListener()`. Platform ordinals are normalized to a shared **0..3** scale (`nominal|fair|serious|critical`). A new all-static `ThermalService` wraps it (NativeEventEmitter, cached last level, drain/Tier-1 threshold helpers).
- **Integration — extend the seam #3 left.** `BackgroundTaskService.shouldPauseProcessing` (`src/services/background/BackgroundTaskService.ts:309`) gains **thermal pressure as a third pause axis** alongside battery-saver and the 00:00–06:00 night window, so the durable drain pauses when hot — protecting **any** heavy pass, **including Tier-0**. `ThermalService.initialize()` is primed from `BackgroundTaskService.initialize()`.
- **Integration — expose the Tier-1 check.** `DeviceCapabilityService.canRunTier1()` composes capability eligibility **AND** thermal (Tier-1 threshold) into the single check the **OrchestratorService / Tier-1 selection** will consult when #4+ adds a `tier1_gemma` drain (`OrchestratorService.ts:21` already notes "Tier-1 (Gemma) enqueues a different value later"). No Gemma, no Tier-1 drain, and no `content://` decoding is wired here — this is the gate infra Tier-1 consults.
- **Asymmetric failure policy.** The thermal *pause* fails **open** (a broken/absent module ⇒ treat as `nominal`, never wedge the pipeline — consistent with `battery.ts`); the Tier-1 *admission* fails **closed** (unknown/error ⇒ ineligible, Tier-0 only — never OOM a weak device on a guess).

## Capabilities

### New Capabilities
- `device-capability-gating`: the JS capability gate — a coarse, cached RAM/disk/ABI eligibility policy over `react-native-device-info` that decides whether a device may ever run Tier-1, with a live free-disk headroom re-check and a `canRunTier1()` composition (capability AND thermal) that fails closed; a failing device silently stays Tier-0-only.
- `thermal-state-observer`: the `ThermalObserver` TurboModule (iOS `ProcessInfo.thermalState` + notification, Android `PowerManager.getCurrentThermalStatus()` + listener) exposing a normalized 0..3 getter and change event on both platforms, its Android manual package registration / iOS `RCT_EXTERN_MODULE` auto-registration, and the `ThermalService` JS wrapper (event-cached level, fail-open, drain/Tier-1 threshold helpers).

### Modified Capabilities
- `queue-drive-and-gating`: the existing requirement **"The drain runs under BackgroundTaskService gating and checkpointing"** is extended so `shouldPauseProcessing` also pauses the drain under **thermal pressure** (a third axis beside battery-saver and the night window), protecting any heavy pass including Tier-0. No other requirement in that spec changes.

## Impact

- **New JS:** `src/native-modules/NativeThermalObserver.ts` (TurboModule spec), `src/services/device/DeviceCapabilityService.ts`, `src/services/device/ThermalService.ts`; one added key in `src/utils/constants/storage-keys.ts` (`DEVICE_CAPABILITY_SNAPSHOT`).
- **New native (iOS):** `ios/Visara/Thermal/ThermalObserverModule.swift` + `ThermalObserverModule.m` (`RCT_EXTERN_MODULE(..., RCTEventEmitter)` — auto-registers, no AppDelegate edit). Deployment target **26.0** (set by #4) ⇒ `ProcessInfo.thermalState`/notification (iOS 11+) are **unconditionally available**; no `@available` guard needed.
- **New native (Android):** `android/app/src/main/java/com/visara/thermal/ThermalObserverModule.java` + `ThermalObserverPackage.java`; one line in `MainApplication.kt` (`add(ThermalObserverPackage())`, mirroring `add(MediaObserverPackage())` at `:22` — this module is manually registered, not autolinked). minSdk **36** (set by #4) ⇒ `PowerManager.getCurrentThermalStatus()`/`addThermalStatusListener()` (API 29+) are **unconditionally available**; no `Build.VERSION` guard needed.
- **Edited JS:** `src/services/background/BackgroundTaskService.ts` — `shouldPauseProcessing` gains the thermal axis (always-on, cached read, no per-tick native round-trip); `initialize()` primes `ThermalService`.
- **Dependencies:** none added — `react-native-device-info@^14.1.1` already present; thermal is a first-party native module.
- **Untouched:** `ProcessingService` engine seam, `OrchestratorService` drain logic (no Tier-1 drain wired here), `MediaObserver` modules, DB/schema, search. Gemma/executorch (#4) is not touched.
- **Conventions:** Biome (tabs, double quotes, `noExplicitAny: error`), strict TS, all-static services, legacy decorators. New/edited JS stays typecheck- and lint-clean. Native pieces require a device/emulator build the human runs (JS-only CI cannot link them).
- **Verify (baseline-relative):** `npx tsc --noEmit` currently reports **8** pre-existing `TS6133` unused-symbol errors in 4 unrelated UI files; this change adds **zero** new typecheck errors (count stays 8).
