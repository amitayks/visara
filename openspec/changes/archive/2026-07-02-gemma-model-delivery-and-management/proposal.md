## Why

Foundation #4 (`executorch-runtime-bootstrap`) proved Gemma-4 E2B multimodal can run on-device, but it accepts the raw first-run behavior of `react-native-executorch`: the ~3.2 GB (iOS MLX) / ~4.4 GB (Android Vulkan) model is fetched **implicitly, ungated, on the first `useLLM` call** the moment any Tier-1 code touches the model. For a shipping app that is unacceptable — it would download multiple gigabytes over cellular, off charger, with no user consent, no free-disk pre-check, no integrity check, and no resume across app kills, and it silently contradicts Visara's onboarding promise of "100% private… without internet." This change makes model acquisition an **explicit, opt-in, Wi-Fi- and charging-gated, resumable, checksummed, observable delivery** that the user controls from Settings — a managed wrapper **around and ahead of** executorch's resource-fetcher — while guaranteeing the app is fully usable on the shipping ML-Kit Tier-0 path until (and unless) the model is present and enabled. It ships delivery + management + the surrounding UX only; wiring Gemma into an active Tier-1 drain remains a later change.

## What Changes

- **A managed delivery service (`GemmaModelDeliveryService`, all-static, JS-only).** It owns a per-platform **model manifest/variant** derived from the executorch getter `models.llm.gemma4_e2b_multimodal()` (source of truth for the `.pte` + `tokenizer.json` + `tokenizer_config.json` URLs; `node_modules/react-native-executorch/src/constants/modelUrls.ts:130-162`) and drives the download **itself** via `@kesha-antonov/react-native-background-downloader` with **OS-enforced Wi-Fi-only** constraints (`isAllowedOverMetered:false`/`isAllowedOverRoaming:false` on Android, `setConfig({ allowsCellularAccess:false })` on iOS) and a **JS charging gate** (`DeviceInfo.isBatteryCharging()`), writing to the **exact path executorch expects** so the later `useLLM` finds files present and skips its own fetch.
- **Resumable + reconciled.** On boot the service re-attaches to any in-flight OS download (`getExistingDownloadTasks()`) and reconciles MMKV state against on-disk reality (`BareResourceFetcher.listDownloadedModels()` + `RNFS.exists`), so a download survives app kill (true background on both platforms via the downloader, unlike RNE's Android `RNFS.downloadFile` foreground path).
- **Checksummed integrity.** After a file lands it is verified with a native streaming hash — `@dr.pogodin/react-native-fs` `hash(path,"sha256")` (streams multi-GB natively, never loads the file into JS) — against a pinned digest; `react-native-quick-crypto` covers the small tokenizer/manifest artifacts. A failed checksum deletes the file and refuses to mark the model ready.
- **State in MMKV + cache placement.** New `STORAGE_KEYS` (`MODEL_DELIVERY_STATE`, `MODEL_ENABLED`) hold the delivery state machine and the opt-in flag; the cache dir (`${directories.documents}/react-native-executorch/`) is created **with `NSURLIsExcludedFromBackupKey:true`** on iOS ahead of RNE so multi-GB weights are excluded from iCloud/iTunes backup.
- **Settings "AI Model" section.** Shows delivery state/progress, **model size vs. free disk** (`DeviceInfo.getFreeDiskStorage()`), the platform **variant**, an **enable toggle** (opt-in, default off), download / pause / cancel / delete-to-reclaim controls, and a **"re-run analysis" hook** (an exposed seam consumed by the future Tier-1 drain — no active Gemma drain is wired here).
- **Onboarding model step + copy reconciliation.** A new onboarding step introduces the optional model download; it **NEVER blocks onboarding** (completion proceeds regardless; the app runs Tier-0 only until the model is present + enabled). The onboarding "100% private… without internet" copy (`src/screens/Onboarding/OnboardingScreen.tsx` — `WelcomeContent`/`PrivacyContent`) is reconciled to "downloads the model once, then works fully offline."
- **Optional Android AICore / Gemini-Nano fast-path.** Where a device exposes AICore/Gemini-Nano, the service MAY select an `aicore` variant that **skips the ~4.4 GB download** entirely. This is specified as an optional, capability-detected path + seam (no first-party AICore API exists in the current dep set), not a built native bridge.
- **No active Tier-1 drain, no schema change, no engine swap.** Consistent with #5, this change **exposes** delivery state + the enable flag + the re-run seam but wires **no** consumer into the Tier-0 drain; `ProcessingService`/`OrchestratorService`/`EngineRegistry` are untouched. `EngineRegistry.getById("gemma")` still resolves `undefined` until a later change registers the engine.

## Impact

- **New JS:** `src/services/model/GemmaModelDeliveryService.ts` (all-static delivery/state machine/gating/checksum/reconcile), `src/services/model/gemmaModelManifest.ts` (variant + URL/size/digest manifest derived from `models.llm.gemma4_e2b_multimodal()`), a Settings "AI Model" component (organism/section under `src/components/organisms/`) + `SettingsScreen`/`SettingsDrawer` wiring, and a new onboarding step in `src/screens/Onboarding/OnboardingScreen.tsx`.
- **Edited JS:** `src/utils/constants/storage-keys.ts` (add `MODEL_DELIVERY_STATE`, `MODEL_ENABLED`); onboarding privacy copy in `OnboardingScreen.tsx` (`WelcomeContent`, `PrivacyContent`); a boot-time `GemmaModelDeliveryService.initialize()` prime (e.g. alongside `OrchestratorService.initialize()` in `src/components/system/OrchestratorBridge.tsx:39` or `App` bootstrap) that only reconciles state and never auto-starts a download.
- **Dependencies:** none added — `@dr.pogodin/react-native-fs@^2.39.1` (`package.json`), `@kesha-antonov/react-native-background-downloader@^4.5.6`, `react-native-quick-crypto@^0.7.17`, `react-native-device-info@^14.1.1`, and `react-native-mmkv@^3.3.3` are all present (added by #4 or pre-existing). The optional AICore path is explicitly NOT implemented as a native bridge here.
- **Untouched (guaranteed):** `ProcessingService` engine seam + `ProcessingResult`, `OrchestratorService` drain/enqueue (`processNext`/`maybeStartDrain`), `EngineRegistry`, DB/schema, search, `index.js` `initExecutorch` block, the executorch POC screen. No Gemma engine is registered and no `tier1_gemma` work is enqueued.
- **Interaction with executorch:** the delivery service pre-places files at RNE's exact destination (`${RNEDirectory}${getFilenameFromUri(url)}`, `react-native-executorch-bare-resource-fetcher/lib/handlers.js`) so `useLLM` short-circuits its own download; this couples to RNE's path/URL convention (pinned `0.9.2`) and is a POC-verify item.
- **Conventions:** Biome (tabs, double quotes, `noExplicitAny: error`), strict TS, all-static services, `@services/@models/@shared-types` aliases. New/edited JS stays typecheck- and lint-clean.
- **Verify (baseline-relative):** `npx tsc --noEmit` currently reports **8** pre-existing `TS6133` unused-symbol errors in 4 unrelated UI files; this change adds **zero** new errors (count stays 8), plus a Metro-bundle check and `npm run lint`.
- **POC-dependent (re-tune after #4 gate):** exact model byte-sizes and pinned checksums, the pinned model-version string (must match what a future Gemma engine stamps as `ai_model_version` for the re-run idempotency guard), free-disk headroom slack, whether pre-placement (vs. delegating RNE's own `ResourceFetcher.fetch`) is the chosen mechanism, and whether the Android AICore fast-path is pursued.
