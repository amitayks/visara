## Why

Foundations #1–#5 shipped a v2 schema whose `media_files` rows carry `ai_model_version` / `ai_schema_version` / `processed_at` (`src/services/database/schema.ts:27-30`), a durable `processing_queue` with `task_type` / `model_version` (`schema.ts:92-93`), a single-drain `OrchestratorService` with a **version-aware skip guard** (`src/services/orchestrator/OrchestratorService.ts:206-214`), and a `canRunTier1()` capability/thermal gate (#5). But the **existing library was analyzed by the old model** and stays that way: the orchestrator only enqueues *unprocessed* files (`OrchestratorService.ts:363` `if (mediaFile.isProcessed) return;`) and `runInitialProcessing` early-returns once the queue is empty. Nothing re-drives already-processed media when the target model/engine advances. The #3 authors named this gap explicitly and deferred it: *"model-version-aware bulk reprocessing (change #10)"* with *"the idempotency key … ready either way"* (`openspec/changes/archive/2026-07-02-processing-orchestrator-wiring/design.md:181`, `proposal.md:38`). This change realizes that deferred backfill: it re-drives the existing library through the #3 orchestrator when `ai_model_version` no longer matches the current target — broadly for cheap Tier-0, selectively and gated for heavy Tier-1 (Gemma).

## What Changes

- **A model-version-aware reprocessing planner.** A new all-static `LibraryReprocessingService` scans `media_files`, compares each row's stored `ai_model_version` against the current target engine descriptor (`ProcessingService.getEngine().descriptor` / `EngineRegistry`), and **enqueues** the mismatched files into the existing durable `ProcessingQueueRepository` with the right `task_type` / `model_version` / `priority`. It does **not** drain and does **not** run any model — the #3 `OrchestratorService` + #7 Tier-1 drain do that. Reset is **enqueue-then-overwrite-in-place**, never a destructive up-front wipe.
- **Tier-0 backfills broadly; Tier-1 is selective + prioritized.** Every `tier0_mlkit`-stale file is enqueued (cheap, safe). `tier1_gemma` is enqueued only for a **prioritized selection** — favorites first, then recent, then (optionally) recently-opened — never the whole library.
- **Tier-1 admission is never a blanket pass.** Before any Tier-1 reprocess item runs it MUST satisfy a composite gate: #5 `DeviceCapabilityService.canRunTier1()` (capability + live disk + thermal-at-Tier-1) **AND** the device is **charging** **AND** it is inside the Tier-1 (night) window — layered on top of the shared `BackgroundTaskService.shouldPauseProcessing` drain gate, not replacing it.
- **Resumable, idempotent, safe to stop.** The enqueue sweep is checkpointed in MMKV (a cursor + counts) so a killed sweep resumes; re-enqueue is guarded against duplicate active rows; the #3 version-aware skip (`OrchestratorService.ts:206-214`) makes a re-driven item a no-op once it is current. The drain resumability is unchanged (#3's durable queue + `resetStaleProcessing` + `BackgroundTaskService` checkpoint).
- **A user "Re-run analysis" action (Settings).** A new action row in the SettingsDrawer *Processing* section (`src/components/organisms/SettingsDrawer.tsx:197-200`) triggers the reprocess; progress is surfaced through the existing #3 `OrchestratorBridge` → `ProcessingContext` path (no new progress UI).
- **Rollback-if-worse consideration.** A quality gate protects prior enrichment: a Tier-1 pass that returns failure or empty output MUST NOT overwrite a file's existing good caption/description/labels. The exact "worse" predicate is **POC-dependent** on the #4 Gemma gate and is marked for re-tuning.
- **Forward-compatible embedding stream.** The same policy MAY schedule the `embedding` `task_type` (`schema.ts` `embeddings.model_version:110`) for stale/missing vectors, kept distinct from Tier-0/Tier-1 — schedule-only here (no embedding engine is wired), mirroring how #5 exposes `canRunTier1()` without a consumer.

## Capabilities

### New Capabilities
- `library-reprocessing`: the model-version-aware reset/enqueue policy over the existing library — Tier-0 broad backfill, distinct `task_type`/`model_version` streams, a resumable MMKV sweep checkpoint, idempotent/safe-to-stop enqueue that reuses the #3 version-aware skip, overwrite-in-place persistence, the rollback-if-worse quality gate, and the forward-compatible embedding stream.
- `tier1-reprocessing-gate`: the selective, prioritized Tier-1 (Gemma) selection (favorites → recent → recently-opened) and the composite admission gate `canRunTier1()` **AND** charging **AND** night — the single predicate the #7 Tier-1 drain consults, never a blanket pass.
- `reprocessing-user-action`: the Settings "Re-run analysis" action — its surface, confirmation, idempotent trigger, and reuse of the existing progress reporting.

## Impact

- **New JS:** `src/services/orchestrator/LibraryReprocessingService.ts` (all-static planner + Tier-1 admission predicate); one added key `REPROCESS_CHECKPOINT` in `src/utils/constants/storage-keys.ts`.
- **Edited JS:** `src/components/organisms/SettingsDrawer.tsx` (+`onReRunAnalysis` prop + a *Processing*-section action row, styled like the existing confirm-then-act rows at `:291-315`); `src/screens/Settings/SettingsScreen.tsx` (+handler wiring the action to `LibraryReprocessingService.requestReprocess()`).
- **Reused, unchanged:** `OrchestratorService` drain + version-aware skip (#3), `ProcessingQueueRepository.create` / `getNextPendingByTaskType` (#3), `BackgroundTaskService` durable checkpoint + `shouldPauseProcessing` (#3/#5), `DeviceCapabilityService.canRunTier1()` + `ThermalService` (#5), `src/utils/device/battery.ts` (`getBatteryStatus`/`isDeviceCharging`), `MediaFileRepository.updateWithProcessingResult` persist shape, `SearchService.addToIndex` incremental refresh.
- **Dependencies:** #3 (orchestrator/queue/checkpoint), #5 (`canRunTier1`), #7 (the Tier-1 **Gemma** `AnalysisEngine` + `tier1_gemma` drain stream — the consumer of the Tier-1 enqueue and admission predicate). No new npm dependency; no DB/schema change (every column already exists from #1).
- **Untouched:** DB schema, the Tier-0 `MlKitEngine`/`ProcessingService` seam, the persist write shape, `SearchService` internals, all native modules.
- **POC-dependent (re-tune after the #4 Gemma gate):** the rollback-if-worse "worse" predicate; the Tier-1 selection breadth, recency window, priority bands, and whether daytime Tier-1 is permitted.
- **Conventions:** Biome (tabs, double quotes, `noExplicitAny: error`), strict TS, all-static services, legacy decorators, `@services`/`@models`/`@utils` aliases. New/edited JS stays typecheck- and lint-clean.
- **Verify (baseline-relative):** `npx tsc --noEmit` currently reports **8** pre-existing `TS6133` unused-symbol errors in 4 unrelated UI files; this change adds **zero** new typecheck errors (count stays 8), plus a Metro-bundle resolve check and Biome lint.
