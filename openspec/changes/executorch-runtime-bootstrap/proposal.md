## Why

The Visara ML-Kit → on-device-Gemma-4 migration cannot proceed until we prove that `react-native-executorch`'s **Gemma-4 E2B multimodal** model actually *runs* vision inference on-device (returns a real caption for a real image) inside *this exact app* — RN 0.81.4, React 19.1.0, New Arch / Fabric / Hermes / bridgeless. This change is the **GO/NO-GO gate for the whole migration**: it fully integrates the Executorch runtime on both platforms, ships an isolated dev-only proof-of-concept screen, and defines the acceptance criteria the human executes on real hardware. Building is not enough — the gate is *running*. It must be possible for this gate to fail without destabilizing the shipping ML-Kit path.

## What Changes

- **Add the pinned Executorch dependency set** (JS, both platforms): `react-native-executorch@0.9.2`, the bare adapter `react-native-executorch-bare-resource-fetcher`, and its peers `@dr.pogodin/react-native-fs` + `@kesha-antonov/react-native-background-downloader`. All four are currently ABSENT from `package.json` (RN 0.81.4, React 19.1.0). This app has a Podfile ⇒ **bare** adapter, not Expo.
- **Wire global runtime init** at the very top of `index.js` (currently 5 lines), *before* `AppRegistry.registerComponent` (`index.js:5`): `initExecutorch({ resourceFetcher: BareResourceFetcher })`. Skipping this throws `ResourceFetcherAdapterNotInitialized` at the first hook call.
- **iOS — CocoaPods autolinking (NOT SPM), static linking, newest-only floor.** RNE ships no Swift Package; it vendors a prebuilt `ExecutorchLib.xcframework` + an `opencv-rne` pod. Bump the iOS floor to **26.0** (stakeholder newest-only override, SUPERSEDING the podspec's 17.0): edit `ios/Podfile:9` (`platform :ios, '15.5'` → `'26.0'`) and **all four** `IPHONEOS_DEPLOYMENT_TARGET = 15.5` occurrences in `ios/Visara.xcodeproj/project.pbxproj` (lines 342, 369, 439, 511). Keep static linking (do NOT set `USE_FRAMEWORKS`; `ios/Podfile:12-16` leaves it conditional/off) and keep the existing `post_install` fmt-consteval patch (`ios/Podfile:33-60`). `pod install` pulls RNE + `opencv-rne` via autolink (`ios/Podfile:19` `use_native_modules!`).
- **Android — Gradle autolink + arm64-only + newest-only minSdk.** Autolinks via `android/settings.gradle:3` + `android/app/build.gradle:54` (`autolinkLibrariesWithApp()`); no `MainApplication.kt` edit. Constrain the ABI to **`arm64-v8a`** (RNE supports only `arm64-v8a`/`x86_64`) via a tracked `ndk { abiFilters 'arm64-v8a' }` block in `defaultConfig`. Bump **minSdk 24 → 36** (Android 16, stakeholder newest-only override) at `android/build.gradle:4`; `compileSdk`/`targetSdk` are already 36 (`android/build.gradle:5-6`), NDK 27.1.12297006 (`android/build.gradle:7`).
- **Ship an isolated dev-only POC screen** that directly calls `useLLM({ model: models.llm.gemma4_e2b_multimodal() })`, gates UI on `llm.isReady`, shows `llm.downloadProgress`, feeds `sendMessage` a **decodable local `file://` image path** (a bundled test JPEG copied to a file path, or the `file://` output of `ThumbnailService.generateThumbnail()` at `src/services/media/ThumbnailService.ts:326` — **never** a raw `content://` MediaStore URI), and renders the streamed `llm.response`. Reachable only behind a `__DEV__` entry point.
- **Define the acceptance gate**: an agent-run **arm64 iOS/iPadOS 26 Simulator** build/install/launch smoke (inference expected to FAIL — MLX has no CPU fallback), plus a **human-run on-device inference proof** on an **M-class iPad Pro** (its Apple GPU runs the MLX model) and an **Android flagship 12 GB+** (NO iPhone), with a metrics results table and explicit GO/NO-GO criteria recorded in `design.md`.
- **Do NOT touch the shipping ML-Kit path.** `ProcessingService.processMedia`'s `Promise.all` seam (`src/services/ml/ProcessingService.ts:34-37`) and the `ProcessingResult` contract (`ProcessingService.ts:7-13`) stay unmodified. No schema writes, no embeddings/search/audio, no `ExecutorchService` — those come *after* GO.

## Impact

- **Dependencies (added, pinned):** `react-native-executorch@0.9.2`, `react-native-executorch-bare-resource-fetcher`, `@dr.pogodin/react-native-fs`, `@kesha-antonov/react-native-background-downloader`. iOS transitively pulls `opencv-rne (~> 4.11.0)` + a prebuilt `ExecutorchLib.xcframework` (arm64-device + arm64-simulator slices only — no `x86_64` sim slice, so only Apple-Silicon Macs build the sim). Android pulls prebuilt `.so` via prefab (arm64-v8a).
- **iOS config (edited):** `ios/Podfile:9` (platform 26.0); `ios/Visara.xcodeproj/project.pbxproj` lines 342, 369, 439, 511 (`IPHONEOS_DEPLOYMENT_TARGET = 26.0`). This raises the app's iOS floor to 26.0 (newest-only). Static linking preserved; fmt-consteval `post_install` patch preserved.
- **Android config (edited):** `android/build.gradle:4` (`minSdkVersion = 36`); `android/app/build.gradle` `defaultConfig` gains `ndk { abiFilters 'arm64-v8a' }`. Note: `android/gradle.properties` is absent on disk + gitignored (`.gitignore:136-137` — `android/gradle.properties`, `*.properties`), so ABI config lives in the *tracked* `app/build.gradle`, not an untracked local `reactNativeArchitectures`.
- **JS (edited/new):** `index.js` gains the `initExecutorch` block above `AppRegistry.registerComponent`; a new dev-only POC screen + a `__DEV__`-gated entry point; bundled test JPEG asset(s). No path-alias change.
- **Untouched (guaranteed):** `src/services/ml/ProcessingService.ts` (the `Promise.all` seam `:34-37` and `ProcessingResult` `:7-13`), `ImageLabelingService`/`TextRecognitionService`, DB/schema, search, `MainApplication.kt`, `MediaObserver` native modules.
- **First-run download:** ~3.2 GB MLX `.pte` (iOS) / ~4.4 GB Vulkan `.pte` (Android) fetched at runtime from Software Mansion's HuggingFace by the background downloader — Wi-Fi only for the POC.
- **Conventions:** Biome (tabs, double quotes, `noExplicitAny: error`), strict TS; new/touched JS files stay lint/typecheck-clean. Scripts: `npm run typecheck` (`tsc --noEmit`), `npm run lint` (`biome check .`).
- **Out of scope (post-GO):** wiring Gemma into `ProcessingService`, an `ExecutorchService`, schema writes, replacing ML Kit, embeddings/search, audio.
